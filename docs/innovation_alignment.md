# 三项创新点的实现边界

| 创新点 | 当前实现 | 验证与边界 |
| --- | --- | --- |
| 完整代码输出限制与阶梯式提示 | 编程对话通过模型指令和最终输出过滤限制完整函数及代码块；同一主题按反问、反例、线索递进。代码练习按提交次数给出同样的三级提示。 | 普通概念问题仍优先完整回答。代码输出过滤是文本级防线，不能保证识别所有伪装的代码表达；需要继续用真实模型测试。 |
| 基于运行测试的精准错误诊断 | 两个固定 Python 练习在 Docker Linux 容器内运行固定用例，返回首个失败用例、输入、预期与实际输出；容器关闭网络、只读挂载并限制资源。 | 当前电脑未安装 Docker，因此此处只完成了命令和 API 的自动化模拟检查，尚无真实容器运行结果。未配置时明确返回 `SANDBOX_UNAVAILABLE`，绝不在服务进程执行学生代码。目录外任意题目和多语言编译尚未实现。 |
| 学习过程追踪与教学联动 | SQLite 保存对话、诊断证据、代码提交、运行结果与提示阶段；教师页面展示学生提问、薄弱点、代码提交和诊断时间线。 | 当前教师页面只适合本机演示，缺少正式身份认证、课程班级成员管理和真实课堂试用。 |

这三点是作品方向，展示或提交材料时应明确区分当前可用功能与待完成的教学验证。
