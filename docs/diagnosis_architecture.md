# 对话诊断架构

`data/data_structures/` 保存概念、常见误区与有区分力的诊断题。目录是教学词典，不是错误答案穷举表。当前有 52 个概念、46 个误区、7 个固定诊断题；扩展条目是工程草案，必须由课程教师审核后才能视为教学内容。

每条新对话先生成对当前需求的完整解答，再考虑诊断：概念映射 → 原话证据抽取 → 已知/目录外假设 → 置信度门槛 → 必要时选择或生成诊断题。这里的“先”指教学决策和最终回复顺序；当前接口仍在诊断完成后一次性返回完整回复。普通提问没有错误证据，不会自动附加测验。对于“为什么 X 都是 O(n²)”这类带可判断前提的提问，模型另行检查前提是否确实错误；若证据足够，只作为待核验线索，先纠正事实，再追问判断依据并给出具体情境题。提问本身不更新长期误区记录，后续回答才能支持确诊。明确的可疑说法也会先得到解释，再说明关键区别并提出核验题。低置信度不触发主动核验；高置信度仍需核验，不由单次模型判断直接确诊。等待核验时若学生改问新问题或请求解释，原核验中断，优先回答新需求。

核验回答再次交给模型评估，要求引用回答原文且达到当前工程阈值 0.8，否则保持 `UNCERTAIN`。模型可能出错，阈值也不是经过验证的校准概率。正式用于教学前应以教师标注集做误诊率与置信度校准。

2026-09 的在线检查发现结构化证据模型有时会把“我认为普通 BST 查找一定是 O(log n)”漏判为纯提问。现在只对具有明确断言标记的短句使用原文保底证据；如果结构化假设仍为空，再尝试与少量人工维护的高频误区匹配。保底结果仍只标为 `SUSPECTED`，需核验题支持才能确认。这个机制是有限兜底，不能代替开放式诊断模型。

所有观察与核验结果写入 `learning_evidence`。只有 `MASTERED` 或 `GAP` 核验结果才能更新长期概念状态。概念状态采用 Beta 证据计数：初始 alpha=1、beta=1，答对增加 alpha，确认缺口增加 beta；掌握度是 alpha/(alpha+beta)，可信度按证据条数/(证据条数+2) 展示。二者是可解释的工程指标，不是经实证校准的真实掌握概率。

目录内误区保留其稳定 ID；目录外候选用 `OPEN:` 键单独记录，可在教师端“目录外新问题候选”查看。当前没有教师审核与合并流程，不能自动写回人工目录。`SUSPECTED`、`CONFIRMED`、`IMPROVING`、`RESOLVED` 是不同状态，不将知识缺口与误区混为一谈。

无 API Key 的 Mock 模式只展示少量知识卡，并且不对开放式核验题给出可靠确诊。真实 API 模式的结构化诊断流程已有实现和模拟测试，尚未用真实模型与教师标注集验证。
